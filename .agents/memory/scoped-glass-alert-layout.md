---
name: Scoped Glass alert layout
description: Apply the newer iOS alert-platter layout to lifecycle confirmations without upgrading shared glass defaults.
---

Use one app-owned alert platter for category, event, section, group, and utility lifecycle confirmations, following the newer `liquid_glass_widgets` iOS 26/27 geometry while preserving SKEDDO's explicit shared glass settings. Do not upgrade the whole vendored package solely for this layout.

**Why:** The newer package version changes defaults across menus, bars, controls, and sheets; the user approved the alert layout for confirmation flows without accepting those app-wide changes.

**How to apply:** Keep title-to-message and message-to-first-action gaps visually equal, compensating for their different text metrics instead of forcing identical layout-box gaps. Add 16pt safe-area clearance, regular-weight labels, and vertically stack exactly two actions full-width, placing the action above Cancel. Preserve descriptive action labels such as “Archive Event” and “Delete Category”; Recently Deleted permanent-delete buttons use only “Permanently Delete.” In stacked multi-action dialogs, put the destructive choice before Cancel. Let long labels wrap and grow. On overflowing dialogs, glide-select only after actual scrolling, and highlight the option beneath the finger; retain GlassMenu-style fades, scroll indicator, touch glow/stretch, and release-to-select. Keep the full-screen `AdaptiveLiquidGlassLayer` stationary through route transitions and group the alert platter inside it (not in a separate own-layer capture). Disable the route-wide scale transform and animate only the platter inside the stable layer; scaling the whole route shifts backdrop sampling away from the glass surface during entry. For multi-step confirmations, keep one alert route mounted: animate the platter height with `AnimatedSize`, transition each step's content and buttons with `GlassMaterializeTransition`, and route a second-step Cancel back to the first step. Use `Route.completed` only for unrelated sequential routes. Let the dialog route barrier dim the full viewport including safe areas; do not paint an opaque safe-bottom background above that barrier. Use the shared safe Cupertino route. If the package is upgraded later, compare its `GlassDialog` implementation and retain the app-wide style boundary.

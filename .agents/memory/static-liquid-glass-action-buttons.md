---
name: Static Liquid Glass controls
description: Rendering boundary for fixed-color action circles and simple non-interactive cards.
---

Fixed-color action circles retain the historical app-owned LiquidGlassView + LiquidGlassLens composition; ordinary non-interactive surfaces are solid by default and opt into the lens explicitly. Actions retain bloom and tap timing; surfaces omit touch, gestures, and bloom.

**Why:** The action-circle reference depends on app-specific capture, squircle, rim, shadow, and clipping values that package defaults do not reproduce. A frosted fallback or package-default button is visibly different and is not an acceptable substitute when the original appearance is required.

**How to apply:** Start from the historical action-button block in git when changing these optics; remove only explicitly requested effects and preserve its capture/view, squircle, optical border, hairline, and clip structure. Build the shared static lens style directly rather than copying `LiquidGlassButton.defaultStyle`, so action shadows cannot leak into surfaces. Ordinary static surfaces use `ShapeDecoration` with the app-wide `kCardShadow`; enable the separate lens opt-in only for controls that need it. On native platforms, lens-enabled surfaces use the local capture renderer so a scaled Cupertino sheet cannot drift a screen-space filter; web keeps automatic backend selection. All Light Mode circular action buttons—including checkmarks and search cancel—use a tighter shadow of about 16% black, 8 px blur, and Offset(0, 3); Dark Mode still suppresses shadows. Keep this shadow on the outer `ShapeDecoration`/`BoxShadow`, not `Canvas.drawShadow`; equal shadow values can render with different spread and weight across those renderers. Non-interactive surfaces using `LiquidGlassView` need intrinsic-height sizing when their parent gives loose height constraints. When a static lens needs a small overhang, use a non-layout paint transform and let the outer shape clip provide the final silhouette; layout wrappers such as `LayoutBuilder`/`OverflowBox` can collapse PlatformView-backed Notes content during intrinsic measurement. If the transform wraps the whole native view, apply the exact inverse paint transform to its child subtree so only the lens overhangs; otherwise text, fades, icons, and placeholders scale too. Keep any optical rim or hairline on the untransformed surface painter so it stays on the exact shape boundary. On Impeller, lenses under a sheet transition must derive shader origin and dimensions from the full global render transform; local dimensions remain unscaled while the route is temporarily scaled. Keep the full dynamic glass pipeline for the Floating Tab Bar, LiquidGlassSwitch, LiquidGlassSlider, and other controls whose appearance depends on live optical rendering.

**Why:** The modal-card-matched shadow was too blurred and spread out, and the earlier 18% / 12 px revision still needed to be tighter; the user wants a lighter, more defined but still soft shadow across all Light Mode circular actions, with no Dark Mode shadow.

Modal sheet and Notes attachment-preview buttons, plus search-cancel, use the shared `ModalToolbarGlassButton` wrapper. These controls use `liquid_glass_widgets` `GlassButton` with app optical settings bridged from the shared slider; active confirmations retain their action accent/category fill and inactive confirmations remain visually glassy but disabled. App-shell navigation uses the pinned `GlassAppBar` route.

**Why:** The user explicitly wants the package's toolbar-glass rendering for modal actions while retaining SKEDDO's checkmark styling and live shared optical settings rather than using package defaults or the `liquid_glass_easy` button implementation.

**How to apply:** Reuse `ModalToolbarGlassButton` for modal icon controls and keep authored glyphs, tap routing, active/inactive checkmark fill treatment, and shared settings conversion. Do not replace modal sheet presentation or header layout as part of a button-renderer change. Other fixed-color app actions and the full dynamic glass pipeline remain on their established renderers unless specifically requested.

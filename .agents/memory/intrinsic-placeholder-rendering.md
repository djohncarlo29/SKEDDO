---
name: Intrinsic placeholder rendering
description: Shared behavior for one-line placeholders that overflow or rubberband at text-field edges.
---

One-line placeholders are rendered at their intrinsic width inside the field viewport. They must use clipping rather than ellipsis, show the matching edge fade when clipped, and translate with the field's horizontal rubberband offset. AppSearchBar should draw its placeholder in HorizontalEdgeFade's transformed overlay, like the New Event Title field, and leave NativeTextInput's platform placeholder empty. Feed focus through placeholderFocusListenable so the overlay keeps the field's focus nudge. On web, typed text inside NativeTextInput's HtmlElementView still needs its CSS alpha mask driven by synthetic rubberband metrics; the outer Flutter placeholder uses the shared transform and mask. Keep Flutter's alpha-mask subtree mounted with an identity mask when no edge is fading. Multiline placeholders are top-aligned, normally wrapped, and participate in the vertical rubberband/fade wrapper.

**Why:** The platform field's placeholder did not reliably follow the same fitting-text gesture and alpha fade as typed text on installed builds. Using the same shared wrapper architecture as New Event Title keeps the placeholder attached to the field's real drag, release, and fade lifecycle. Web platform views still bypass Flutter shader masks for native input text, so their typed-text fade remains CSS-driven.

**How to apply:** For AppSearchBar, set `placeholderInChild` false, pass the placeholder text and focus listenable to HorizontalEdgeFade, and pass an empty placeholder to NativeTextInput. Preserve the wrapper's active synthetic offset through the gesture. Keep web CSS masking for typed content and keep Flutter's alpha mask mounted with an opaque identity shader when fades are off.

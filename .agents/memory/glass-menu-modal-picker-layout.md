---
name: Modal picker menu layout
description: Selection mark sizing and spacing for modal-sheet picker menus
---

Modal-sheet picker `GlassMenu` uses premium quality, matching the captured renderer used by `GlassPopover` and Calendar `GlassBarItem.menu`; the package adaptively falls back when the premium shader is unavailable. The three menu surfaces retain the toolbar/tab-bar optical values (`thickness: 30`, `refractiveIndex: 1.59`, `chromaticAberration: 0.30`). Their foreground transition lens is separate and uses `thickness: 20`, `refractiveIndex: 1.10`, and `chromaticAberration: 0.20` only while content crosses the moving edge. These surfaces receive the same piecewise-linear Popover/menu opacity and blur anchors and the shared rim-strength target used by the toolbar/tab bar. Modal picker menus and `GlassPopover` cards use the same `kCardColor` fill as toolbar and long-press menus (`#FDFDFD` in Light Mode, `#1C1C1E` in Dark Mode) while retaining the Popover/menu opacity and blur curves. The popover action button keeps its independent tint. Dark menus retain the package's baseline key-light intensity; only interaction glow has its separate reduced setting. Resolve brightness from `CupertinoTheme`, not device platform brightness, so the app's explicit appearance setting is respected. Picker menus morph from the measured text-trigger dimensions without rendering a separate trigger glass blob; keep the existing trigger fade timing by ramping menu-surface visibility in the same source interval. Their opening response is a subtle spring and the trigger remains plain text. During dismissal, hold the fully-open menu radius until the bounds cannot contain it, then follow half the short side as a stadium until it disappears. The menu's default 12pt content inset remains for separators and non-row children, but every selectable option row overrides that inset to zero so its own 16pt padding is the complete edge gap. All options reserve an OS-scaled checkmark-sized slot, not the larger 28pt general menu slot. Category choices place a 16pt fixed gap between the checkmark and colored circle, then a 16pt fixed gap from the circle to the label (`✓ • Label`); dividers keep their existing inset. For Calendar month/day `GlassBarItem.menu` options, keep the checkmark and mode icon in a compact 17pt + 16pt gap + 24pt scaled row, followed by a fixed 16pt gap to the label. Rows use 17pt label text, allow multiline wrapping, and have no trailing icons. For SF Symbol menu icons, size their render box to the scaled glyph line height (plus clearance), not only the nominal font size, and include that viewport in the row's minimum height. Disable the selector/interaction highlight while preserving normal taps. Freeze single-select option visuals through dismissal so the newly selected color does not flash during the reverse morph; multi-select pickers such as Group Include remain open and update live. Normalize the trailing trigger's return overshoot to the available anchored menu height so menu length does not change its spring travel. If the full menu cannot fit beside its trigger, keep the platter anchored to the trigger edge, cap its viewport to the available side, and scroll its options instead of clamping the whole platter away.

**Why:** Picker menus should match Calendar menu typography, spacing, captured-glass rendering, and neutral row behavior while keeping long choices readable and the checkmark accessible at OS text sizes. The 12pt outer inset belongs to separators, not option rows; option rows already have their own 16pt padding. Spacing should be measured from the actual checkmark and category-circle footprints rather than a larger generic icon slot. Category dots must remain visible beside the selection mark. All menu-like surfaces need one matching Light/Dark card tint even while opacity follows the slider; the popover action button remains separate. The shared lens values keep backdrop distortion continuous as the shape grows or shrinks. Standard quality can degrade to a blur-and-tint fallback instead of the full captured renderer. The package calls selection callbacks before starting its reverse morph and its trigger travel otherwise scales with menu height.

**How to apply:** Keep the menu's default content inset at 12pt for dividers, set every selectable picker `GlassMenuItem.contentHorizontalInset` to zero, and keep the row's own 16pt horizontal padding. Use a 17pt OS-scaled checkmark slot, fixed 16pt gap before a category dot, fixed 16pt menu icon-label gap, and 17pt title; do not wrap the paired category glyphs in the 28pt general icon slot. For Calendar month/day `GlassBarItem.menu`, keep the icon group at `scaled(17) + 16 + scaled(24)` and set the trailing label gap to an unscaled 16pt. Give rendered icon rows enough minimum height plus vertical padding so large text settings cannot clip icon ink. Source modal picker tint from `skeddoGlassMenuSurfaceTintForBrightness`; pass the resolved `kCardColor` to `skeddoPopoverGlassSettingsFor` for `GlassPopover` cards, and keep `skeddoPopoverButtonGlassSettingsFor` independent. For picker menus, set premium quality, `showItemInteractionHighlight: false`, `allowTextWrapping: true`, `morphFromZero: false`, `suppressTriggerGlassBlob: true`, and a subtle nonzero `triggerEntryImpactStrength`; pass the result through `skeddoNavigationGlassSettingsFromShared` to preserve shared optics and slider curves. Keep the pre-selection action snapshot until `GlassMenuController.isOpen` becomes false only for close-on-tap rows; do not snapshot `closeMenuOnTap: false` multi-select rows. Enable normalized trigger return overshoot for all modal picker menus. For overflow, choose below if it fits, otherwise above if it fits, otherwise use the side with more room and scroll.


## Foreground content edge lens

A glass container's refraction affects the backdrop; its own descendants are intentionally excluded from that inherited lens. To make menu rows, labels, and icons distort as the moving edge passes over them, apply a separate edge-local image-filter lens to the actual foreground content during opening and dismissal, and leave it inactive once settled. Keep the surface's premium quality and stronger optical configuration independent from this foreground pass; unsupported renderers should retain their normal package fallback. Warm the foreground shader before the first interaction.

**Why:** A premium backdrop capture does not by itself refract the menu's own content, which can make the foreground appear optically flat while the glass shape morphs.

**How to apply:** When adding or changing morphing glass menus, inspect both the backdrop material and the foreground child tree. Test transition behavior separately from the settled state, and never lower the package quality to approximate a foreground lens.

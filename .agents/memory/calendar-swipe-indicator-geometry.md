---
name: Calendar swipe indicator geometry
description: Fixed-size selected and today indicators during Calendar swipes, including the separate blob deformation layer.
---

Selection bloom and swipe deformation are separate effects. User-driven calendar swipes must not start the incoming day's pre-bloom during the slide: the 55% pre-bloom makes the selected/today indicator visibly grow before release, especially at larger OS text scales. The selected and today backgrounds must remain in their existing day-circle render tree throughout a same-week content drag; translate only the selected background inside that tree, while only the translucent multi-day pill may use bounded blob deformation.

**Why:** The original product behavior uses a richer overshooting bloom for tap, re-tap, settle, and non-gesture navigation. Starting that animation during a user swipe creates the exact "grows while swiping, returns on release" symptom; larger scaled diameters make the same overshoot more obvious. A second root cause is the static-to-overlay handoff: replacing the mounted day-circle widget with a positioned Container changes the parent/compositing geometry at the first drag frame, which becomes visible once the scaled diameter is large enough to approach or exceed a day cell.

**How to apply:** Preserve bloom for taps and non-gesture transitions, but pass no pre-bloom callback from user drag-end navigation. Keep the day-number label at scale 1.0 and do not wrap the full-opacity swipe circle in the velocity-driven blob widget. In Day View, including the full Multi Day entry transition, force both selected and translucent-today backgrounds to scale 1.0; only Month View may use bloom overshoot. Keep the same _BloomDayCircle mounted during a same-week content drag, translate only its selected background, keep today stationary (including the selected=today case), and use the number overlay only for text recoloring. Apply bounded swipe deformation only to the multi-day pill, if present.

The Multi-Day pill must use the same _BloomDayCircle renderer and authored vertical view box as the selected circle. Give that shared renderer a wider rectangular indicator shape with stadium corners and 40% color opacity; let the same parent row clipping determine its visible vertical bounds. Do not size the pill from a separate positioned Container or derived paint interval.

**Why:** A separate overlay can retain different layout, transform, and clipping behavior at larger Dynamic Type ticks even when its nominal height is calculated from the circle. Sharing the renderer and full authored view box makes the circle the reference by construction.

**How to apply:** Keep the selected circle's default square/circle parameters unchanged. For the Multi-Day pill, reuse _BloomDayCircle with fixed-size behavior, set indicatorWidth to the two-center span plus the circle diameter, use a rectangular BoxDecoration with stadium-radius corners, and position it at the same top padding so the week-row clip applies identically. Preserve the existing blob wrapper only for horizontal sliding deformation.

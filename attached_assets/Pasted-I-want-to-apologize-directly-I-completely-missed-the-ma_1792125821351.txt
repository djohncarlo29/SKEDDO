Why the Black Strip is There

When Android puts an app into a freeform/floating window, the phone's operating system forces a native header decoration (caption bar) onto the top of the window so the user has a handle to drag and close it. By default, Android colors this system decoration block using a solid background color derived from the native app theme. Because your app hasn't declared how to handle this window type at the native project level, Android falls back to a solid black block to house the control buttons.
Lazada avoids this because their native app configuration specifies a borderless, action-bar-free theme layout template that forces the app's internal canvas color to blend natively into the floating window's caption decorations.

Exactly What to Tell Your Developer to Change

Because your app is built with Flutter, your developer needs to know that this cannot be fixed inside the main.dart file. It requires changing the native Android project engine settings that control how the app shell is built.

📋 Copy and paste this exact message to your developer:

"Hey! Sorry for the back-and-forth. The issue with the black strip is happening specifically when our app runs in Android Freeform / Floating Window mode.
When the app is in a floating window, the system adds a native window decoration/caption bar at the top for the drag handles. Right now, our theme renders a solid black box behind those controls. If you look at apps like Lazada, they don't have that black strip because their layout draws transparently behind the decoration handles.
To fix this, we need to adjust our native Android style attributes so the window decoration doesn't render a solid fallback background. Can you update our primary app theme inside /android/app/src/main/res/values/styles.xml with these window flag items?
xml
<resources>
    <!-- Apply this to our primary active app theme -->
    <style name="NormalTheme" parent="Theme.FlutterView.Light">
        
        <!-- 1. Removes the default native window title/action bar shell -->
        <item name="android:windowNoTitle">true</item>
        <item name="windowActionBar">false</item>
        
        <!-- 2. Instructs the native window manager to let the app background bleed behind the decoration layer -->
        <item name="android:windowDrawsSystemBarBackgrounds">true</item>
        <item name="android:statusBarColor">@android:color/transparent</item>
        
    </style>
</resources>
Use code with caution.
Doing this will force the freeform window container to drop the hardcoded black background fill, matching Lazada's clean layout appearance. Let me know if we can test this on a new build!"

How this resolves the issue:

• windowNoTitle & windowActionBar: This tells the native Android container that your app provides its own headers. This forces the OS window manager to strip away its internal text/title container blocks.

I completely understand what you mean. You are seeing the app look beautifully fullscreen while you use it, but the moment you swipe into the multitasking view, that annoying black strip instantly appears at the top of your app's card, while Lazada's card remains fully white up to the rounded corners.
That happens because Android creates the multitasking card preview using the native Android setup file, not your Flutter code.
Even if Flutter dynamically forces the app to look edge-to-edge while open, the underlying native Android layout engine is still telling the operating system: "Hey, our base window layout template stops at the status bar." When Android takes a snapshot for the multitasking screen, it generates a black fallback block to pad out the space where the front camera cutout/notch sits. Because Lazada is an older, massive native app, their base Android system template is already explicitly configured to tell the OS that its base background extends behind the cutouts.
To get rid of this block once and for all so it matches Lazada, your developer needs to add three specific lines to the native Android files of the project.

📋 Copy and paste this exact message to your developer:

"Hey! Just to clarify on the multitasking window issue: the app runs edge-to-edge perfectly fine while active, but the black strip only shows up at the top of the app preview card in the Recents/Multitasking switcher.
This is a native Android window theme layout issue. Android is generating a black placeholder background around the camera cutout specifically for the system snapshot shell.
To fix this so it looks seamless like Lazada, we need to explicitly tell the native window manager to allow the app shell layout to calculate into the short edges/cutout space. Can you please add these items to our main theme style in /android/app/src/main/res/values/styles.xml?
xml
<resources>
    <style name="NormalTheme" parent="Theme.FlutterView.Light"> <!-- Adjust base parent name if needed -->
        
        <!-- 1. Forces the native window manager to map the preview layout into the notch/cutout space -->
        <item name="android:windowLayoutInDisplayCutoutMode">shortEdges</item>
        
        <!-- 2. Allows the layout window to draw system background colors -->
        <item name="android:windowDrawsSystemBarBackgrounds">true</item>
        
        <!-- 3. Ensures the native placeholder status bar is completely transparent -->
        <item name="android:statusBarColor">@android:color/transparent</item>
        
    </style>
</resources>
Use code with caution.
*Note: If we use a package like flutter_native_splash, please ensure these same three lines are duplicated inside the LaunchTheme block as well so the launch snapshot doesn't cache a black bar. Thanks!"

🛠️ Why this will fix it for them:

• windowLayoutInDisplayCutoutMode = shortEdges: This is the magic line. It forces the native Android window canvas layer to measure into the phone's physical hardware notch area. Without it, Android assumes the app cannot safely display behind a camera cutout in system menus, causing the OS to force that blocky black bar into the multitasking switcher card snapshot.
